# WinTools 0.17.1 发布操作说明（给维护者）

本文是把源码变成可分发安装包的**可执行步骤**。面向刚接手的维护者，从零开始只需照做。

---

## 一、发布前检查（缺一不可）

1. **测试全绿**：在仓库根目录依次运行，486 个测试应全部通过。

   ```bash
   dotnet test tests/WinTools.Core.Tests/WinTools.Core.Tests.csproj
   dotnet test tests/WinTools.Tools.Tests/WinTools.Tools.Tests.csproj
   dotnet test tests/WinTools.DiscoveryTests/WinTools.DiscoveryTests.csproj
   ```

2. **版本号四处一致**：`src/WinTools.Shell/WinTools.Shell.csproj` 的 `<Version>` / `<AssemblyVersion>` / `<FileVersion>`、`src/WinTools.Shell/app.manifest` 的 `assemblyIdentity version`、`installer/WinTools.iss` 的 `MyAppVersion`、`CHANGELOG.md` 顶部条目。发新版本时一起改。

3. **关闭占用进程**：若本机正运行着 WinTools.Shell.exe 或杀软锁定 DLL，先退出，否则编译/发布会报"文件被占用"。

## 二、生成发布产物

在仓库根目录执行。先 Release 编译整个解决方案，确保所有工具 DLL 已生成并复制到 Shell 的 Release 输出目录；再发布（**注意 `PublishSingleFile=false`**，原因见第四节）：

```bash
dotnet build WinTools.sln -c Release -m:1
dotnet publish src/WinTools.Shell/WinTools.Shell.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -o publish -m:1 --disable-build-servers
```

然后把工具 DLL 补进发布目录（Shell 故意不引用工具项目，发布不会自动带上它们）：

```bash
cp src/WinTools.Shell/bin/Release/net10.0-windows/WinTools.Tools.*.dll publish/
```

验证 `publish/` 下应有：`WinTools.Shell.exe`、`WinTools.Core.dll`、`WinTools.Services.dll`、4 个 `WinTools.Tools.*.dll`（源码共可发现 24 个工具，含「屏幕截图」；截图工具在既有 `WinTools.Tools.File.dll` 内，随该 DLL 自动收录，无需新增拷贝项），以及大量 `*.dll` 和语言子目录（cs/de/zh-Hans 等）。

---

## 三、编译安装包

> 若启用签名（自签名或正式证书），**先**按第六节签好 `publish/` 里的 `WinTools*.exe` / `WinTools*.dll`，再执行下面的 ISCC——文件一旦打进安装包就无法单独签了。

本机已安装 Inno Setup 7.1.1（位于 `D:\Inno Setup 7\`）。在仓库根目录执行：

```bash
"/d/Inno Setup 7/ISCC.exe" installer/WinTools.iss
```

产物：`installer-output/WinTools-0.17.1-setup.exe`（自包含运行时，lzma2 压缩后约 36 MB）。编译应为 `Successful compile` 且无警告。

图形界面方式：用 Inno Setup Compiler 打开 `installer/WinTools.iss`，按 F9。

若宿主程序正在运行、`publish/` 里的 DLL 被占用导致发布失败，可先把 `dotnet publish -o` 指到另一个目录（如 `publish-071`），再从该目录打包：

```bash
"/d/Inno Setup 7/ISCC.exe" "--define=PublishDir=..\publish-071" installer/WinTools.iss
```

`PublishDir` 不传时默认 `..\publish`，常规流程不变。

## 四、关键坑位：为什么不能用单文件发布

本项目工具靠运行时扫描 `WinTools.Tools.*.dll` 反射发现。若用 `PublishSingleFile=true`，工具 DLL 会被打进单文件，扫描不到，程序里 24 个工具会全部消失。因此**发布必须用 `PublishSingleFile=false`**，让工具 DLL 作为独立文件安装在程序目录。详见 `docs/阶段八-安装包制作与发布.md` 第 4.3 节。

> `docs/阶段八` 第 4.1 节的示例命令是教学用的单文件模板，实际发布以本文第二节为准。

## 六、分发与签名

### 6.1 现实约束（2026 现状）

- **自签名 ≠ 消除警告**：SmartScreen 照常提示，只是弹窗里显示固定发布者名而非"未知发布者"。自签名只用来跑通签名链、演练流程。
- **EV 自 2024 起不再绕过 SmartScreen**：OV / EV 的新文件都要靠下载量积累声誉，不要为"免警告"多花 EV 的钱。
- 公开分发两条路：**OV 证书 Authenticode**（国内约 ¥1200–4400/年，个人可申请，私钥需硬件 Token）或 **Microsoft Store MSIX**（个人注册现已免费，微软重签，用户零警告）。
- Azure Artifact Signing（约 $9.99/月、免硬件 Token）**个人仅限美国/加拿大**，国内个人不适用。

### 6.2 自签名内测流程（当前采用）

证书 `certs/wintools-selfsigned.pfx` 与密码 `certs/.password` 都在 `certs/` 下，`.gitignore` 已屏蔽整个目录，**绝不入库**。证书仅在文件中，未导入 Windows 证书存储，删除目录即可彻底撤销。

首次生成证书（仅需一次，RSA 2048 / SHA256 / 代码签名 EKU / 5 年有效期）：用 .NET `CertificateRequest.CreateSelfSigned()` 生成后导出 pfx，密码写入 `certs/.password`。已有证书时跳过此步。

日常发布签名顺序（**内部 PE 必须先签**，否则打进安装包后无法再签）：

```powershell
# 1) dotnet publish 之后、ISCC 之前：签 publish 里的 WinTools.*.exe / *.dll
powershell -File installer\sign.ps1 -Path publish

# 2) ISCC 生成 setup.exe 之后：签安装包；-Timestamp 加 RFC3161 时间戳（需联网）
powershell -File installer\sign.ps1 -Path installer-output\WinTools-0.17.1-setup.exe -Timestamp

# 3) 便携 ZIP 直接用已签名的 publish 目录压缩（见第七节），无需再次签名
```

脚本会自动定位最新版 Windows SDK 的 `signtool.exe`，只签 `WinTools*.exe` / `WinTools*.dll`，**不碰第三方运行时 DLL 的微软签名**；末尾打印每个文件的签名状态与签名者。自签名证书未导入本机信任存储时状态显示 `NotTrusted` 属预期；要看到 `Valid` 需把 pfx 导入当前用户"受信任的根证书颁发机构"（会改变本机信任设置，按需决定）。

签名不会消除 SmartScreen 提示——内测时仍需告知测试者点击"更多信息 → 仍要运行"。正式公开分发按 6.1 升级为 OV 或 Store MSIX。

内测可走 GitHub Releases 直接分发已签名的 setup.exe。

## 七、免安装便携版 ZIP

用户要"单独打包 WinTools.Shell.exe"时，**不能只给 exe**：`ToolDiscovery` 运行时扫描同目录的 `WinTools.Tools.*.dll`，少了 DLL 就发现不到任何工具。正确做法是把整个 `publish/` 目录打成 ZIP。

在仓库根目录执行（排除 .pdb，输出到 `installer-output/`）：

```powershell
$src = 'D:\Desktop\WinTools\publish'
$dst = 'D:\Desktop\WinTools\installer-output\WinTools-0.17.1-portable.zip'
$items = Get-ChildItem -LiteralPath $src -Force | Where-Object { $_.Extension -ne '.pdb' }
Compress-Archive -Path $items.FullName -DestinationPath $dst -CompressionLevel Optimal -Force
```

产物：`installer-output/WinTools-0.17.1-portable.zip`。解压后双击 `WinTools.Shell.exe` 即可；`WinTools.Core.dll`、`WinTools.Services.dll` 与 4 个 `WinTools.Tools.*.dll`（共 24 个工具）必须与 exe 保持同目录。
