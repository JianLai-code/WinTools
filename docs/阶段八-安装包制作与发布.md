## 4. 第一步：dotnet publish 生成单文件

### 4.1 发布命令

在 `src/WinTools.Shell` 项目目录执行：

```bash
dotnet publish -c Release -r win-x64 --self-contained true ^
  -p:PublishSingleFile=true ^
  -p:IncludeNativeLibrariesForSelfExtract=true ^
  -p:EnableCompressionInSingleFile=true ^
  -o ../../publish
```

### 4.2 关键参数解释（初学者向）

| 参数 | 作用 | 为什么这样设 |
|------|------|-------------|
| `-c Release` | 发布版编译 | 优化过的正式版本，非调试版 |
| `-r win-x64` | 目标运行时 Windows 64 位 | 对应主流 Win10/11 |
| `--self-contained true` | 把 .NET 运行时一起打包 | **关键**：用户机器无需预装 .NET，双击即用（对应阶段七"干净裸机"测试） |
| `PublishSingleFile=true` | 打成单个 exe | 分发简单，用户不用面对一堆 DLL |
| `IncludeNativeLibrariesForSelfExtract=true` | 把原生库也打进单文件 | 避免运行时缺 DLL |
| `EnableCompressionInSingleFile=true` | 压缩单文件 | 减小体积，代价是启动稍慢（对工具箱可接受） |

### 4.3 插件 DLL 的处理（重要）

阶段三架构里，工具是运行时扫描 `WinTools.Tools.*.dll` 发现的。单文件发布默认会把引用的 DLL 也打进去，这**可能破坏反射发现机制**。两种处理方式，二选一并写进验收：

- **方案 A（推荐，简单）**：发布时不把工具 DLL 打进单文件，让 `.iss` 把工具 DLL 作为独立文件一起安装到程序目录。发布命令加 `-p:PublishSingleFile=false`，或对每个工具项目单独 publish 后拷贝。
- **方案 B（进阶）**：保持单文件，把工具改为编译期注册（放弃反射发现）——但这违背阶段三"新增工具零改宿主"的架构目标，**不推荐**。

> **验收动作**：打包后必须在全新机器验证"7 个工具全部出现在导航中"。若发现工具缺失，几乎都是这里的原因——按方案 A 调整。

### 4.4 版本信息

在 `WinTools.Shell.csproj` 中设置，让生成的 exe 带 standard 版本资源：

```xml
<PropertyGroup>
  <Version>1.0.0</Version>
  <AssemblyVersion>1.0.0.0</AssemblyVersion>
  <FileVersion>1.0.0.0</FileVersion>
  <Product>WinTools 轻量级工具箱</Product>
  <Company>YourName</Company>
</PropertyGroup>
```

## 5. 第二步：Inno Setup 安装脚本

### 5.1 脚本模板（`installer/WinTools.iss`）

以下是一份可直接改用的完整脚本。初学者只需替换 `YourName`、版本号、路径占位。

```iss
#define MyAppName "WinTools 轻量级工具箱"
#define MyAppVersion "1.0.0"
#define MyAppPublisher "YourName"
#define MyAppExeName "WinTools.Shell.exe"

[Setup]
AppId={{8F3C2A1E-5D7B-4A6F-9C31-2E8B7A4D1F60}
AppName={#MyAppName}
AppVersion={#MyAppVersion}
AppVerName={#MyAppName} {#MyAppVersion}
AppPublisher={#MyAppPublisher}
DefaultDirName={autopf}\WinTools
DefaultGroupName={#MyAppName}
OutputDir=..\installer-output
OutputBaseFilename=WinTools-{#MyAppVersion}-setup
Compression=lzma2
SolidCompression=yes
WizardStyle=modern
PrivilegesRequired=lowest
ArchitecturesInstallIn64BitMode=x64
UninstallDisplayIcon={app}\{#MyAppExeName}
VersionInfoVersion={#MyAppVersion}

[Languages]
Name: "chinesesimplified"; MessagesFile: "compiler:Languages\ChineseSimplified.isl"

[Tasks]
Name: "desktopicon"; Description: "创建桌面快捷方式"; GroupDescription: "附加任务："

[Files]
Source: "..\publish\WinTools.Shell.exe"; DestDir: "{app}"; Flags: ignoreversion
Source: "..\publish\WinTools.Tools.*.dll"; DestDir: "{app}"; Flags: ignoreversion
Source: "..\publish\*.dll"; DestDir: "{app}"; Flags: ignoreversion recursesubdirs

[Icons]
Name: "{group}\{#MyAppName}"; Filename: "{app}\{#MyAppExeName}"
Name: "{autodesktop}\{#MyAppName}"; Filename: "{app}\{#MyAppExeName}"; Tasks: desktopicon
Name: "{group}\卸载 {#MyAppName}"; Filename: "{uninstallexe}"

[Run]
Filename: "{app}\{#MyAppExeName}"; Description: "立即运行 WinTools"; Flags: nowait postinstall skipifsilent
```

### 5.2 关键指令说明

| 指令 | 作用 | 为什么这样设 |
|------|------|-------------|
| `PrivilegesRequired=lowest` | **不要求管理员权限安装** | 呼应阶段五最小权限：安装到用户目录、无需 UAC；也避免提权带来的兼容问题 |
| `DefaultDirName={autopf}\WinTools` | 默认安装到 Program Files（non-admin 时自动转到用户目录） | 符合 Windows 惯例 |
| `ArchitecturesInstallIn64BitMode=x64` | 64 位安装模式 | 配合 Inno Setup 7 64 位版 |
| `Compression=lzma2` + `SolidCompression=yes` | 高压缩率 | 减小安装包体积 |
| `WizardStyle=modern` | 现代安装向导样式 | 界面观感与 Win10/11 一致 |
| `ChineseSimplified.isl` | 中文安装界面语言 | 目标用户是中国用户（阶段一 D6） |
| `[Tasks] desktopicon` | 让用户选择是否建桌面图标 | 尊重用户选择，不擅自污染桌面 |
| `AppId` 那一长串 GUID | 卸载识别的唯一标识 | **一旦发布就不要改**，改了会被识别成另一个软件、无法覆盖升级 |

> **坑位提醒**：`{autopf}` 在 `lowest` 权限下会安装到用户 AppData 而非 Program Files——这是有意为之，保证普通用户无需管理员即可安装。若你更希望装到 Program Files（需管理员），把 `PrivilegesRequired` 改为 `admin`，但要相应处理 UAC 弹窗。两者取舍在自检清单里确认。

### 5.3 编译安装包

用 Inno Setup 编译器打开 `.iss`，按 `F9` 编译；或命令行：

```bash
ISCC.exe installer\WinTools.iss
```

产物在 `installer-output/WinTools-1.0.0-setup.exe`。

## 6. 第三步：代码签名策略（沿用阶段五结论）

### 6.1 现实约束回顾（阶段五已查证，此处落地）

- **EV 证书自 2024 年起不再绕过 SmartScreen**——买 EV 为"消除警告"是多花钱，不推荐。
- **自签名 = 等同未签名**，系统会显示强警告，仅适合内测。
- **个人开发者公开分发的两条路**：① OV 证书 Authenticode 签名（约 $150-300/年，仍需积累信誉）；② Microsoft Store（MSIX 打包，微软重签名，无 SmartScreen 警告）。

### 6.2 本项目的分阶段策略

| 阶段 | 签名方式 | 目的 | 用户体验 |
|------|---------|------|---------|
| 内测（v0.x ~ v1.0-rc） | **自签名** | 验证签名流程，不花成本 | 有警告，但告知测试者即可 |
| 公开分发（v1.0+） | 二选一：OV 签名 / Store MSIX | 消除/降低安全警告 | 视选择而定 |

### 6.3 自签名操作（内测用）

```bash
# 1. 生成自签名证书（PowerShell）
$cert = New-SelfSignedCertificate -Type CodeSigningCert `
  -Subject "CN=YourName" -KeyUsage DigitalSignature `
  -FriendlyName "WinTools Dev Cert" -CertStoreLocation "Cert:\CurrentUser\My"

# 2. 导出为 pfx（设置密码）
$pwd = ConvertTo-SecureString -String "your-password" -Force -AsPlainText
Export-PfxCertificate -cert $cert -FilePath "wintools-dev.pfx" -Password $pwd
```

在 Inno Setup 的 `[Setup]` 段加签名配置，或编译后用 `signtool sign` 对安装包签名：

```iss
[Setup]
SignTool=signtool sign /f "..\certs\wintools-dev.pfx" /p "your-password" /fd sha256 $f
```

> **安全提醒**：pfx 私钥和密码**绝不提交到 Git**——加入 `.gitignore`。这是阶段五"供应链安全"的一部分。

## 8. 第五步：发布渠道与版本日志

### 8.1 发布渠道对比

| 渠道 | 优点 | 缺点 | 适合 |
|------|------|------|------|
| **GitHub Releases** | 免费、无审核、版本管理清晰 | 新手访问有门槛；无签名仍警告 | 开发者用户、内测分发 |
| **个人官网 + 直链** | 面向普通用户友好 | 需域名/托管；无签名仍警告 | 有自己网站时 |
| **Microsoft Store (MSIX)** | 微软重签名，无 SmartScreen 警告；自动更新 | 需注册开发者账号（个人约 $19/年）、审核周期 | 追求普通用户体验的正式发布 |

**推荐路径**：内测走 GitHub Releases；正式版若面向普通用户且重视"无警告体验"，优先 Store（MSIX）。这与阶段五结论一致。

### 8.2 版本日志（CHANGELOG）

每个发布版本写一份 `CHANGELOG.md`，格式采用"保持一个 CHANGELOG"惯例：

```markdown
# 更新日志

## [1.0.0] - 2026-11-18
### 新增
- 首批 7 个工具：哈希校验、JSON 格式化、系统信息、批量重命名、端口查询、Base64、随机密码
### 修复
- （本版无）
### 已知问题
- 自签名版本首次运行会触发 SmartScreen 提示

## [0.5.0] - 2026-xx-xx
...
```

版本号语义（延续到阶段九）：`主版本.次版本.补丁`——重大改版加主版本，新增功能加次版本，仅修 bug 加补丁。
