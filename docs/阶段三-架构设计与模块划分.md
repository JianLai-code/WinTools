## 1. 本阶段要做成什么、不做成什么

- ✅ 要做成：技术选型说明、统一 `ITool` 接口、工具发现机制、仓库目录结构、空工具验证方案。
- ❌ 不做成：具体工具的业务逻辑、完整界面代码——那是阶段六的事。
- 🎯 完成标志（对应路线图验收标准）：写一个**不含业务逻辑的空工具**，能被主程序自动发现并显示在界面上，而**宿主核心代码零改动**。

## 2. 重大修正：.NET 版本从 8 改为 10

阶段一推荐了 .NET 8，但那是基于旧信息。查证微软官方支持策略（2026-11-18）：

| 版本 | 类型 | 状态 | 终止支持 |
|------|------|------|---------|
| .NET 11 | STS | 活动（刚发布，2026-11-10） | 2028-11-14 |
| **.NET 10** | **LTS** | **活动（推荐）** | **2028-11-14** |
| .NET 9 | STS | 已终止 | 2026-11-10 |
| .NET 8 | LTS | 已终止 | 2026-11-10 |

**结论：本项目目标框架定为 `net10.0-windows`（.NET 10 LTS）。**

- 理由一：.NET 8 已停止安全补丁，新项目不应基于已 EOL 的版本。
- 理由二：LTS 提供 3 年支持，与本项目"长期维护"定位匹配；.NET 11 虽新但为 STS（2 年），且刚发布不宜尝鲜。
- 补充：.NET 10 的 WinForms 与 .NET 8 的写法基本一致，初学者资料通用，切换成本极低。

> 本修正只影响目标框架编号，不影响前两阶段的任何需求或范围结论。

## 3. 技术选型说明

| 维度 | 选择 | 理由 | 备选与否决原因 |
|------|------|------|--------------|
| 语言 | C# | Windows 原生生态最好，资料最多 | — |
| 目标框架 | .NET 10 LTS | 当前受支持 LTS，支持到 2028-11 | .NET 8 已 EOL；.NET 11 太新 |
| UI 框架 | WinForms | 拖拽设计器、低资源、学习曲线平缓 | WPF 更现代但 XAML 门槛高，二期再评估 |
| 插件发现 | 反射 + 特性标记 | 新增工具不改宿主代码 | 手写注册表需改宿主，否决 |
| 配置存储 | JSON 文件（用户目录） | 零依赖、易读易改 | 注册表不便于迁移 |
| 日志 | 轻量文本日志 | 排障够用，无第三方依赖 | — |
| 测试 | xUnit | .NET 主流单元测试框架 | — |
| 打包 | 单文件发布 + Inno Setup | 安装体验好（阶段八细化） | — |

**明确不用**：Electron/Avalonia（资源占用高）、WPF（二期再说）、任何需要联网账号的框架（违反阶段一 D3）。

## 4. 总体架构与依赖规则

沿用阶段一的四层架构，这里补充**依赖方向**——这是"新增工具不改宿主"的关键：

```
        ┌──────────────┐
        │ WinTools.Shell│  宿主：主窗口、导航、工具发现
        └──────┬───────┘
               │ 依赖（编译期）
      ┌────────┴─────────┐
      ▼                  ▼
┌───────────┐      ┌──────────────┐
│ .Services │      │ .Tools.*     │  各个工具模块
│ 设置/日志  │      │ 哈希/JSON/...│
└─────┬─────┘      └──────┬───────┘
      │ 依赖               │ 依赖
      └────────┬───────────┘
               ▼
        ┌──────────────┐
        │ WinTools.Core│  接口契约（零依赖）
        └──────────────┘
```

依赖规则（务必遵守，否则架构会腐化）：

1. **Core 零依赖**：只放接口、特性、公共模型，不引用任何其他项目。
2. **Services 依赖 Core**：实现设置、日志等公共服务。
3. **Tools.* 依赖 Core**（可选依赖 Services）：工具之间**互不依赖**。
4. **Shell 依赖 Core + Services**，但**不编译期引用具体工具**——运行时按文件名扫描 `WinTools.Tools.*.dll` 并反射加载。

第 4 条是整个架构的核心：宿主对工具是"运行时发现"而非"编译期写死"，所以新增工具只需丢一个符合命名约定的 DLL 进来，宿主代码一行不用改。

## 5. 统一接口定义（Core 项目）

### 5.1 ITool.cs

```csharp
using System.Drawing;
using System.Windows.Forms;

namespace WinTools.Core;

/// <summary>
/// 所有工具必须实现的统一接口。
/// 宿主只依赖此接口，不依赖任何具体工具类。
/// </summary>
public interface ITool
{
    /// <summary>唯一标识，用于设置存储与导航定位</summary>
    string Id { get; }

    /// <summary>显示名称</summary>
    string Name { get; }

    /// <summary>分类，用于左侧导航分组</summary>
    string Category { get; }

    /// <summary>图标，可为 null（宿主会用文字首字代替）</summary>
    Icon? Icon { get; }

    /// <summary>创建工具主界面，每次打开调用一次</summary>
    Control CreateUI();
}
```

### 5.2 ToolAttribute.cs

```csharp
namespace WinTools.Core;

/// <summary>
/// 标记一个实现类是可被发现的工具，并控制导航顺序。
/// 元数据（Id/Name/Category）由 ITool 属性提供，此处只放发现所需信息，避免重复维护。
/// </summary>
[AttributeUsage(AttributeTargets.Class, Inherited = false, AllowMultiple = false)]
public sealed class ToolAttribute : Attribute
{
    /// <summary>导航排序，越小越靠前</summary>
    public int Order { get; init; } = 100;
}
```

## 6. 工具发现机制（Shell 项目）

### 6.1 发现器 ToolDiscovery.cs

```csharp
using System.Reflection;
using WinTools.Core;

namespace WinTools.Shell;

public static class ToolDiscovery
{
    /// <summary>
    /// 扫描指定目录下所有 WinTools.Tools.*.dll，
    /// 找出带 ToolAttribute 且实现 ITool 的类型并实例化。
    /// </summary>
    public static IReadOnlyList<ITool> DiscoverFromDirectory(string appDirectory)
    {
        var found = new List<(int Order, ITool Tool)>();
        var pattern = "WinTools.Tools.*.dll";

        foreach (var dll in Directory.GetFiles(appDirectory, pattern))
        {
            Assembly asm;
            try { asm = Assembly.LoadFrom(dll); }
            catch { continue; } // 坏 DLL 不应导致整个程序崩溃

            foreach (var type in asm.GetTypes())
            {
                if (type.IsAbstract || !typeof(ITool).IsAssignableFrom(type)) continue;
                if (type.GetCustomAttribute<ToolAttribute>() is not { } attr) continue;

                try
                {
                    var tool = (ITool)Activator.CreateInstance(type)!;
                    found.Add((attr.Order, tool));
                }
                catch { /* 实例化失败的工具跳过，记录到日志（阶段五细化） */ }
            }
        }

        return found.OrderBy(x => x.Order)
                    .ThenBy(x => x.Tool.Name)
                    .Select(x => x.Tool)
                    .ToList();
    }
}
```

### 6.2 主窗口如何使用（示意，非完整实现）

## 7. 空工具验证方案（验收标准的落地方式）

写一个**不含业务逻辑**的空工具，验证"自动发现 + 零改宿主"。

```csharp
// 文件：src/WinTools.Tools.Hello/HelloTool.cs
using System.Drawing;
using System.Windows.Forms;
using WinTools.Core;

namespace WinTools.Tools.Hello;

[Tool(Order = 999)]
public sealed class HelloTool : ITool
{
    public string Id => "hello";
    public string Name => "示例工具";
    public string Category => "其他";
    public Icon? Icon => null;

    public Control CreateUI()
    {
        return new Label
        {
            Text = "如果你看到这句话，说明工具已被自动发现。",
            Dock = DockStyle.Fill,
            TextAlign = ContentAlignment.MiddleCenter
        };
    }
}
```

**验证步骤**：

1. 编译解决方案，确认 `WinTools.Tools.Hello.dll` 生成在应用目录。
2. 启动 Shell，左侧导航出现"其他 → 示例工具"。
3. 点击该项，内容区显示提示文字。
4. **关键验证**：删除这个 DLL，重新编译启动——宿主源代码**一行未改**，导航里该项自动消失。

满足以上四步即达成阶段三验收标准。

## 8. 仓库目录结构

```
WinTools/
├── src/
│   ├── WinTools.Core/              # 接口契约（零依赖）
│   │   ├── ITool.cs
│   │   └── ToolAttribute.cs
│   ├── WinTools.Services/          # 公共服务
│   │   ├── Settings/JsonSettingsService.cs
│   │   └── Logging/TextLogger.cs
│   ├── WinTools.Shell/             # 宿主外壳
│   │   ├── MainForm.cs
│   │   └── ToolDiscovery.cs
│   ├── WinTools.Tools.File/        # 文件类：F1 哈希、F2 批量重命名
│   ├── WinTools.Tools.Text/        # 文本类：T1 JSON、T2 Base64、T4 密码
│   ├── WinTools.Tools.System/      # 系统类：S1 系统信息、S2 端口查询
│   └── WinTools.Tools.Hello/       # 验证用空工具（定稿后可删）
├── tests/
│   ├── WinTools.Core.Tests/
│   └── WinTools.Tools.Tests/
├── installer/                      # 阶段八：Inno Setup 脚本
├── docs/                           # 各阶段文档
└── WinTools.sln
```

命名约定（必须遵守，发现器依赖它）：

- 工具项目名以 `WinTools.Tools.` 开头，输出 DLL 才会被扫描到。
- 每个工具一个类，实现 `ITool` 并标注 `[Tool]`。
- 新增工具的标准动作：**建项目 → 实现接口 → 打特性 → 编译**。宿主代码零改动。
