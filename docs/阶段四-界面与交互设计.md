# 阶段四交付物：界面与交互设计

> 项目：轻量级 Windows 工具箱（WinTools）
> 阶段目标：让所有工具拥有一致、可预测、无需说明书的操作体验
> 状态：已定稿（用户已确认界面布局与交互规范，2026-11-18）
> 日期：2026-11-18
> 上游依据：`阶段三-架构设计与模块划分.md`（已定稿，7 个 MVP 工具）
> 配套原型：`prototype/原型-主界面.html`（可点击的界面原型）

---

## 1. 本阶段要做成什么、不做成什么

- ✅ 要做成：主窗口布局、导航方式、统一控件规范、交互流程、主题与无障碍约定、可用性验证方案、可点击原型。
- ❌ 不做成：真实业务逻辑、工具的具体算法——那是阶段六的事；原型只演示界面与交互。
- 🎯 完成标志（对应路线图验收标准）：**新手在无人指导下 1 分钟内能完成任意工具的核心操作**，且所有工具的返回与报错样式完全一致。

## 2. 主窗口布局

### 2.1 布局结构

采用"左侧分类导航 + 右侧内容区"（对应阶段三的分类）：

```
┌────────────────────────────────────────────────────┐
│ 标题栏：WinTools        [搜索工具]   [设置] [—][□][×] │ 40px
├────────────┬───────────────────────────────────────┤
│            │ 面包屑：文件与磁盘 / 哈希校验           │ 36px
│ 左侧导航    ├───────────────────────────────────────┤
│ (200px)    │                                       │
│            │  工具工作区（输入 → 操作 → 结果）        │
│ ▸ 文件与磁盘│  （每个工具在此区域呈现统一结构）        │ 自适应
│   · 哈希校验│                                       │
│   · 批量重命名│                                      │
│ ▸ 文本与编码│                                       │
│   · JSON   │                                       │
│   · Base64 │                                       │
│ ▸ 系统信息  │                                       │
│   · 系统信息│                                       │
│   · 端口查询│                                       │
│            ├───────────────────────────────────────┤
│            │ 状态栏：就绪 / 处理中 / 错误提示         │ 28px
└────────────┴───────────────────────────────────────┘
```

### 2.2 布局决策与理由

| 决策 | 选择 | 理由 |
|------|------|------|
| 导航位置 | 左侧固定 200px | 7-20 个工具时用分类树最清晰，比顶部标签更易扩展 |
| 默认窗口 | 1000×680，最小 860×600 | 兼顾笔记本屏幕，内容区足够放结果表格 |
| 搜索框 | 标题栏内置，支持拼音首字母 | 工具变多后靠搜索快速定位（如"hash""HX""哈希"都能搜到） |
| 状态栏 | 底部常驻 | 统一承载处理结果和错误反馈，避免每个工具各弹窗 |
| 主题 | 浅色为默认，架构预留深色 | 办公场景浅色更普遍；深色放二期 |

## 3. 统一控件规范

所有工具**必须**沿用以下规范，这是"无需说明书"和"报错样式一致"的保证。

### 3.1 视觉基础

- **字体**：微软雅黑 / Segoe UI，正文 9pt（12px），标题 11pt。
- **主色**：蓝 `#185FA5`；成功绿 `#0F6E56`；警告黄 `#BA7517`；错误红 `#A32D2D`。
- **间距**：统一 8px 网格；控件间距 8/16/24px 三档。
- **圆角**：控件 4px，面板 8px。

### 3.2 三类按钮（全工具统一）

| 类型 | 用途 | 样式 |
|------|------|------|
| 主按钮 | 每个工具唯一的主操作（"开始校验""格式化""生成"） | 蓝底白字 |
| 次按钮 | 辅助操作（"浏览…""清空""复制"） | 白底灰边 |
| 危险按钮 | 不可逆操作（批量重命名的"执行"） | 红底白字，且必须二次确认 |

### 3.3 标准零件

- **拖放区**：虚线框 + 图标 + "拖入文件，或点击浏览"；悬停高亮；这是 F1/F2 的统一入口。
- **输入框**：统一高度 32px，占位符写明格式要求（如"输入 1-65535 的端口号"）。
- **结果区**：等宽字体、只读、右上角固定"复制"按钮；多结果用表格。
- **进度反馈**：>1 秒的操作显示进度条 + "取消"按钮，禁止界面假死。
- **状态反馈条**：出现在状态栏，格式为 `[图标] 结果文案`，颜色按语义。

### 3.4 错误提示规范（关键：全工具一致）

统一格式：**图标 + 一句话原因 + 可操作建议**，不弹模态框打断用户。

| 场景 | 文案模板 | 示例 |
|------|---------|------|
| 输入非法 | "输入无效：{原因}。请{如何修正}。" | "输入无效：端口号超出范围。请输入 1-65535。" |
| 文件读取失败 | "无法读取：{文件名}（{原因}）。已跳过，不影响其他文件。" | F1-AC4 |
| 无权限 | "需要管理员权限才能使用此功能。"（仅二期工具） | hosts 编辑 |
| 处理失败 | "处理失败：{原因}。你的原文件未被修改。" | F2 重命名保证 |

> 铁律：**绝不静默覆盖用户文件**（对应 F2-AC2、I2 规格），任何破坏性操作前必须有预览或确认。

## 4. 关键交互流程

所有工具遵循同一个"五步循环"，用户学一次就会用全部工具：

```
① 打开 → ② 输入 → ③ 处理 → ④ 结果 → ⑤ 反馈
  点击导航   拖放/粘贴   进度条    可复制     状态栏
                        可取消    表格/文本
```

- **① 打开**：点击左侧导航项，内容区切换；面包屑同步更新；工具状态保留在内存（切回来不丢失）。
- **② 输入**：拖放区或输入框；输入即时校验，非法时输入框下方给出红字提示，不等待点击操作。
- **③ 处理**：立即给出视觉反馈（按钮变"处理中…"+ 进度条）；超过 1 秒显示可取消。
- **④ 结果**：结果区展示，等宽字体，一键复制；多结果为表格且列头固定。
- **⑤ 反馈**：状态栏给出成功/失败文案；错误按 3.4 规范，不弹窗。

### 4.1 三个代表工具的流程示例

- **F1 哈希校验**：拖入文件 → 自动开始计算 → 进度条 → 三行 MD5/SHA1/SHA256 表格 → 状态栏"校验完成，已计算 1 个文件"。
- **F2 批量重命名**（含二次确认，因是危险操作）：选文件 → 填规则 → 点"预览"显示"原名→新名"对照 → 点"执行"（红色按钮）弹确认 → 执行 → 状态栏"已重命名 5 个文件"，并提供"撤销"。
- **S2 端口占用查询**：输入端口 → 点"查询" → 结果表格（进程名/PID）→ 空闲则状态栏"端口 8080 未被占用"。

## 5. 主题、高 DPI 与键盘/无障碍

- **高 DPI**：WinForms 设 `AutoScaleMode = Dpi`，并在 app.manifest 声明 DPI 感知，避免 4K 屏模糊（对应 Win10 支持决策）。
- **键盘操作**：每个工具都能纯键盘完成——`Tab` 切换焦点、`Enter` 触发主按钮、`Esc` 返回导航。
- **全局快捷键**：`Ctrl+K` 聚焦搜索框、`Ctrl+C` 复制结果区选中内容。
- **无障碍**：Tab 顺序符合视觉顺序；焦点控件有明显描边；颜色不作唯一信息载体（错误图标+文字并存）。

## 6. 可用性验证方案（验收标准的可执行落地）

### 6.1 测试设计

- **对象**：5 名不熟悉本工具box的普通用户（对应 D1"两者兼顾"中的普通用户）。
- **任务**：在无任何说明的情况下，完成"计算一个下载文件的 SHA256 并复制"。
- **通过标准**：**5 人中至少 4 人在 60 秒内独立完成**，且无需提问。
- **观察项**：是否找到哈希工具、是否理解拖放区、是否找到复制按钮、是否误点其他控件。

### 6.2 一致性检查（针对"报错样式一致"）

- 制作一张检查表，逐一触发 7 个工具各 1 个错误场景，截图比对是否符合 3.4 规范。
- 通过标准：7 个错误提示的图标、位置、颜色、句式模板完全一致。

### 6.3 失败处理

若可用性不达标，优先简化失败环节的操作路径（如把"复制"按钮加大、把拖放区提示写得更直白），再复测一次。
